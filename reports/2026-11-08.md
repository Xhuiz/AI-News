## 🌟 重点新闻

### 1. FMF 越狱评分框架：如何量化风险
*   **来源：** Planet AI Aggregate
*   **链接：** [FMF Jailbreak Rating Framework: How It Scores Risk](https://cellcog.ai/blog/frontier-model-forum-jailbreak-rating-framework/)
*   **发生了什么：** OpenAI、Anthropic、Google DeepMind、Microsoft 和 Amazon 等巨头联合支持一种新的越狱评分方法。该方法使用四个 0-3 的量表，结合动态基线和五个风险等级来评估模型的对抗性攻击风险。
*   **为什么重要：** 对于训练师而言，这意味着安全评估有了行业统一的“标尺”。了解这些标准有助于在训练数据清洗和 RLHF（基于人类反馈的强化学习）阶段设定更明确的安全阈值。
*   **初学者学习提示：** 关注“动态基线”的概念。传统的安全测试往往是静态的，而动态基线意味着模型的安全能力会根据上下文和攻击手段的变化而调整，这要求训练师在评估时不能只看单一场景。

### 2. 使用 OpenAI Agents SDK 构建多智能体系统
*   **来源：** Towards Data Science
*   **链接：** [How to Build Multi-Agent Systems with the OpenAI Agents SDK](https://towardsdatascience.com/how-to-build-multi-agent-systems-with-the-openai-agents-sdk/)
*   **发生了什么：** 一篇技术教程展示了如何利用 OpenAI 的 Agents SDK 在 Python 中构建一个包含购车顾问和支持代理的系统。文章详细介绍了 Fan-out（广播）、Pipelines（流水线）、Hierarchies（层级）和 Swarms（蜂群）四种架构模式。
*   **为什么重要：** 单一模型往往难以处理复杂任务。多智能体系统是未来的趋势，学习如何设计 Agent 之间的通信协议和任务分配是高级训练师的核心技能。
*   **初学者学习提示：** 尝试理解“Fan-out”与“Swarm”的区别。Fan-out 通常指一个主 Agent 将任务分发给多个子 Agent 并等待结果，而 Swarm 更强调去中心化的协作和涌现行为。

### 3. Open WebUI v0.13.1：Coding Agents 的集成
*   **来源：** Planet AI Aggregate
*   **链接：** [v0.13.1](https://github.com/open-webui/open-webui/releases/tag/v0.13.1)
*   **发生了什么：** Open WebUI 发布了新版本，引入了 Coding Agents 功能。用户现在可以在终端中直接调用 Claude Code、Codex 和 Pi 等模型，支持语音交互、推理级别选择以及工具请求审批。
*   **为什么重要：** 这展示了“工具使用”在 UI 层面的落地。对于训练师来说，这意味着模型不再仅仅是文本生成器，而是可以调用外部工具的智能体。训练重点应从“生成准确”转向“工具调用正确”。
*   **初学者学习提示：** 注意 Agent 聊天与普通聊天的一个关键区别：**不可再生性**。一旦 Agent 开始执行任务，其对话历史通常不可回滚或修改。这要求在提示词设计中必须确保初始指令的绝对准确性。

### 4. Google Elephant-Goldfish 插件：代码规范审查
*   **来源：** MarkTechPost
*   **链接：** [Google AI Releases Elephant-Goldfish Model Plugin](https://www.marktechpost.com/2026/11/08/google-elephant-goldfish-model-plugin-spec-review-coding-agents/)
*   **发生了什么：** Google 推出了名为 "Elephant-Goldfish" 的模型插件，专门用于代码生成前的规范审查。它会在代码生成前运行 5 个零上下文审查阶段，确保代码符合规范。
*   **为什么重要：** 这体现了“思维链”在代码领域的应用。通过在生成代码前进行自我审查，可以显著降低代码错误率。这对训练师在编写代码生成数据集时提供了参考：即“先规划，后执行”。
*   **初学者学习提示：** 在训练代码生成模型时，可以尝试模仿这种“Spec-First”策略。在 Prompt 中强制模型先输出一个“计划”或“伪代码”，再输出最终代码，往往能提高质量。

### 5. MoE 模型路由机制深度对比
*   **来源：** MarkTechPost
*   **链接：** [Which Routing Does Each MoE Model Use?](https://www.marktechpost.com/2026/11/08/moe-model-routing-comparison/)
*   **发生了什么：** 文章详细对比了 DeepSeek、Qwen、Mixtral、Llama 4 和 gpt-oss 等模型的 MoE 路由机制。内容涵盖了总参数/激活参数、专家数量、Top-K 选择、共享专家以及负载均衡方法。
*   **为什么重要：** MoE（混合专家模型）是当前大模型的主流架构。理解路由机制是优化模型推理速度和准确度的关键。不同的路由策略决定了模型如何分配计算资源。
*   **初学者学习提示：** 关注“负载均衡”。如果路由机制设计不当，某些专家会被频繁调用而“过载”，而另一些专家则闲置。这会导致模型性能下降和计算浪费。

## 📚 今日概念补充

### 1. Spec-First Coding (规范优先编码)
*   **定义：** 一种编程策略，要求 AI 或开发者在生成实际代码之前，先生成详细的技术规范、设计文档或伪代码。
*   **学习价值：** 这是一种“慢思考”策略。对于初学者，这能减少返工率；对于训练师，这是构建高质量代码数据集的有效方法。

### 2. Dynamic Baseline (动态基线)
*   **定义：** 在安全评估中，不是使用固定的“安全/不安全”阈值，而是根据模型当前的上下文、历史交互或攻击复杂度动态调整评估标准。
*   **学习价值：** 现实世界中的攻击是不断进化的，静态规则无法覆盖所有情况。理解动态基线有助于设计更鲁棒的安全护栏。

## 💻 代码示例

### 示例 1：多智能体协作的 Prompt 模板
在构建多智能体系统时，主 Agent 需要明确地分配任务。以下是一个简单的 Python Prompt 模板，模拟“Fan-out”架构。

```python
# prompt_template.py

SYSTEM_PROMPT = """
你是一个任务分发中心。
你的职责是将复杂的用户请求拆解为子任务，并分发给不同的专家 Agent。
请确保每个子任务都有明确的输入和输出格式。
"""

def dispatch_task(user_request):
    # 模拟将任务分发给不同的 Agent
    agents = {
        "planner": "规划专家",
        "coder": "代码编写专家",
        "reviewer": "代码审查专家"
    }
    
    # 构建给主 Agent 的 Prompt
    prompt = f"""
    用户请求: {user_request}
    
    请分析该请求，并决定：
    1. 哪些任务需要规划专家？
    2. 哪些任务需要代码编写专家？
    3. 哪些任务需要代码审查专家？
    
    输出格式 (JSON):
    {{
        "tasks": [
            {{"agent": "planner", "input": "...", "output_format": "..."}},
            {{"agent": "coder", "input": "...", "output_format": "..."}}
        ]
    }}
    """
    return prompt

# 使用示例
req = "帮我写一个 Python 脚本来分析 CSV 文件并生成图表"
print(dispatch_task(req))
```
